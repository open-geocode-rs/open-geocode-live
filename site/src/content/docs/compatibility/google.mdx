OpenGeocode serves Geocoding API v4 and Places API (New) v1. Geocoding returns addresses and coordinates. Places provides search, autocomplete and details.

## Change the endpoint

Send requests to `http://127.0.0.1:8080/compat/google` followed by the Google path, such as `/v4/geocode/address`. Keep your field mask and remove the Google API key.

If you use `@open-geocode/client/google`, change the client configuration. Your existing method call stays the same.

```diff
-const client = google({ apiKey: googleKey });
+const client = google({ baseUrl: "http://127.0.0.1:8080" });
```

## Geocode an address

Look up [the Empire State Building](https://portal.311.nyc.gov/article/?kanumber=KA-01441).

Serve the [USA Pack](/docs/guides/download-packs/). For TypeScript, [build the SDK from source](/docs/guides/typescript/#install-the-client).

<Tabs>
<TabItem label="TypeScript">

```typescript
import { google } from "@open-geocode/client/google";

const client = google({
  baseUrl: "http://127.0.0.1:8080",
});

const { results = [] } = await client.geocode.address({
  addressQuery: "350 Fifth Avenue, New York, NY 10118",
  fieldMask: ["*"],
});

const match = results[0];
console.log(match?.formattedAddress, match?.location);
```

</TabItem>
<TabItem label="cURL">

```bash
curl --get 'http://127.0.0.1:8080/compat/google/v4/geocode/address' \
  -H 'X-Goog-FieldMask: *' \
  --data-urlencode 'addressQuery=350 Fifth Avenue, New York, NY 10118'
```

</TabItem>
</Tabs>

## Supported endpoints

Paths are relative to `/compat/google`.

| Operation | Path | Behavior |
| --- | --- | --- |
| Address geocoding | `GET /v4/geocode/address` | `geocode.address()` |
| Reverse geocoding | `GET /v4/geocode/location` | `geocode.location()` |
| Geocode by place ID | `GET /v4/geocode/places/{placeId}` | `geocode.place()` |
| Destinations | `POST /v4/geocode/destinations` | `geocode.destinations()` returns entrances when the Pack has them. |
| Text and nearby search | `POST /v1/places:searchText`, `POST /v1/places:searchNearby` | `places.searchText()` and `places.searchNearby()`. Nearby results are ranked by distance. |
| Autocomplete | `POST /v1/places:autocomplete` | `places.autocomplete()` |
| Place details | `GET /v1/places/{placeId}` | `places.get()` accepts a place ID returned by OpenGeocode. |

Geocoding v4 also accepts the address and coordinates in the URL path. Use `fieldMask` in the SDK or `X-Goog-FieldMask` over HTTP to select fields.

## Follow-up requests

Use the `placeId` from an OpenGeocode geocode result for Geocoding place lookup. For Places, send the autocomplete result’s `placePrediction.placeId` to Place Details.

## What OpenGeocode leaves out

| Feature | What happens on OpenGeocode |
| --- | --- |
| Geocoding v3 and Places Legacy | Use Geocoding v4 or Places API (New) v1. |
| Photos, reviews and ratings | Place responses omit this content. Photo media requests return an error. |
| Opening status, rating, price and EV filters | `openNow` returns an input error. Minimum rating, price and EV filters return no matches. |
| Google-issued place IDs | Lookups accept OpenGeocode-issued IDs. Search by address or coordinates to replace existing IDs. |
| Popularity ranking and pagination | Nearby Search sorts by distance. Text Search returns one page without a continuation token. |
