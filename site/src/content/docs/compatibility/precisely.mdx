OpenGeocode serves Precisely Geo Addressing v1, Express Autocomplete v2 and Bulk Geo Addressing v2. Use the real-time API for a few addresses or submit a file as a bulk job.

## Change the endpoint

Send requests to `http://127.0.0.1:8080/compat/precisely` followed by the Precisely path. Keep the request body and skip the Precisely token exchange.

If you use `@open-geocode/client/precisely`, change the client configuration. Your existing method call stays the same.

```diff
-const client = precisely({ apiKey: preciselyKey, apiSecret: preciselySecret });
+const client = precisely({ baseUrl: "http://127.0.0.1:8080" });
```

## Geocode an address

Look up [the Space Needle](https://www.spaceneedle.com/contact).

Serve the [USA Pack](/docs/guides/download-packs/). For TypeScript, [build the SDK from source](/docs/guides/typescript/#install-the-client).

<Tabs>
<TabItem label="TypeScript">

```typescript
import { precisely } from "@open-geocode/client/precisely";

const client = precisely({
  baseUrl: "http://127.0.0.1:8080",
});

const { responses } = await client.geocode({
  addresses: [{
    addressLines: ["400 Broad Street, Seattle, WA 98109"]
  }],
  preferences: { maxResults: 1 },
});

const first = responses[0];
const point = first?.results?.[0]?.location?.feature?.geometry;
console.log(first?.status, point?.coordinates);
```

</TabItem>
<TabItem label="cURL">

```bash
curl 'http://127.0.0.1:8080/compat/precisely/v1/geocode' \
  -H 'Content-Type: application/json' \
  --data '{
    "addresses": [
      {
        "addressLines": ["400 Broad Street, Seattle, WA 98109"]
      }
    ],
    "preferences": { "maxResults": 1 }
  }'
```

## Supported endpoints

Paths are relative to `/compat/precisely`.

| Operation | Path | Behavior |
| --- | --- | --- |
| Geocode and reverse geocode | `POST /v1/geocode`, `POST /v1/reverse-geocode` | Results have per-address status. |
| Lookup and verification | `POST /v1/lookup`, `POST /v1/verify` | Use the OpenGeocode reference and the matching country for lookup. |
| Autocomplete | `POST /v1/autocomplete`, `POST /v1/express-autocomplete`, `POST /v2/express-autocomplete`, `POST /v1/autocomplete/postal-city` | Autocomplete includes postal-city search. |
| Proximity and match codes | `POST /v1/proximity-search`, `POST /v1/explain-addresscode` | Proximity Search returns nearby addresses. Explain Address Code reads Global Match Codes. |
| Bulk files | `/v2/files` | Request an upload URL, upload content, list files, or delete a file. |
| Bulk geocoding and verification | `POST /v2/bulk-geocode`, `POST /v2/bulk-verify`, `/v2/bulk/jobs` | List, poll, cancel, and download results from jobs. Jobs start on submission. |

## Follow-up requests

Send the candidate’s `PB_KEY` and country to Lookup. For a bulk job, request an upload URL, upload the file, then submit its `fileId`. Poll the status URL and download the results from the server that created the job.

## What OpenGeocode leaves out

| Feature | What happens on OpenGeocode |
| --- | --- |
| Precisely-issued keys and licensed identifier lookups | Lookup accepts the `PB_KEY` from an OpenGeocode result. Other key types such as `GNAF_PID`, `UDPRN`, `UPRN` and `EIR_CODE` are unsupported. |
| Postal certification and delivery-point validation | Verify and Bulk Verify standardize and match against your Pack. Workflows that require CASS or delivery-point validation need a certified service. |
| Bulk job email | OpenGeocode validates `notifyEmails` but sends no email. Poll the job status for completion. |
| Bulk v1 paths | Use the v2 upload and job endpoints. |
